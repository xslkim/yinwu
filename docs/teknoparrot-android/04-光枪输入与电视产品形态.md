## 1. 背景：为什么 CRT 光枪在现代电视上失效

传统光枪（FC 打鸭子、街机 VR 战警、PS GunCon 等）的原理是**扫描线时序侦测**：
扣下扳机的瞬间，游戏在屏幕上闪出一帧纯白（或白色目标块），枪内的光电传感器侦测到
电子束扫描亮点扫过枪口所指位置的**时间差**，从而反推坐标。这一机制依赖 CRT 的
逐行扫描与零显示延迟（[百度百科：光线枪](https://baike.baidu.com/item/%E5%85%89%E7%BA%BF%E6%9E%AA/6698674)、
[百度贴吧：光枪原理介绍](https://tieba.baidu.com/p/156525412)）。

现代 LCD/OLED 电视是自发光、整帧刷新，且有几十毫秒级的图像处理延迟，CRT 光枪的
时序假设完全不成立。因此**所有现代方案本质上都是"让枪或屏幕端有一个摄像头/传感器来
解算指向坐标"，再把坐标当作鼠标/指针坐标喂给游戏**。这正是本项目的核心选型问题。

## 2. 现代光枪技术方案盘点

### 2.1 Sinden Lightgun（枪内摄像头 + 屏幕白边框）

- **原理**：枪管内置一颗摄像头，游戏画面四周由软件叠加一圈**白色边框**；
  枪端/驱动端通过识别摄像头画面中白边框的透视形变，实时解算出枪口指向的屏幕坐标
  （[MiSTer 社区对 Sinden 原理的描述](https://github.com/MiSTer-devel/Main_MiSTer/issues/819)、
  [Sinden 官方详情页](https://sindenlightgun.com/details/)）。
- **精度**：属于"真光枪"级别，指向即准星，不随时间漂移；官方标称 60fps 追踪，
  "速度与 CRT 光枪相当"（[Sinden Shop 产品页](https://www.sindenshop.com/en-us/products/sinden-lightgun)）。
- **代价**：摄像头输出的是**原始视频流**，必须由主机端软件驱动实时做图像处理，
  约占用 1 GHz 四核 CPU 的一部分算力（[MiSTer FPGA 论坛](https://misterfpga.org/viewtopic.php?t=4292)）。
  还需要游戏画面始终带白边框（全屏时由软件叠加，或模拟器内建支持）。
- **平台支持**：官方明确"目前只支持 Windows 和 Linux，Android 只有非常原始的原型支持"
  （[Sinden Shop 说明页](https://www.sindenshop.com/en-us/pages/information-about-the-sinden-lightgun)、
  [Extreme Hardware 规格页](https://www.extremehardware.co.uk/products/sinden-lightgun-with-recoil)）。
  2024 年 7 月起通过社区定制内核支持 MiSTer FPGA
  （[MrLightgun/MiSTerSindenDriver](https://misterfpga.org/viewtopic.php?t=8091)）。
- **价格**：无后坐力版约 £90–100 / 带后坐力版约 €180
  （[digitalkey.it 报价](https://www.digitalkey.it/en/arcade-parts/345-sinden-lightgun-usb-with-recoil-and-holster.html)）。
- **对本项目的意义**：技术路线最契合"电视 + 自发光屏"场景，但 Android 支持是原型级别，
  且强依赖主机端驱动做视觉解算——若走此路线，**驱动/解算层需要自研移植**。

### 2.2 GUN4IR（开源 DIY，枪内红外摄像头 + 4 点红外灯）

- **原理**：枪内一颗快速红外摄像头（基于 Wii Remote 同源的 PixArt 传感器），
  屏幕四角放置 4 个红外发射点（4 points），枪端固件直接解算坐标，
  以标准 USB HID（鼠标 + 手柄）输出（[GUN4IR GitHub](https://github.com/gobozgz/GUN4IR)、
  [ArcadeControls 发布帖](http://forum.arcadecontrols.com/index.php?topic=161189.0)）。
- **延迟**：官方标称**平均 4ms（2ms 起）**，是市面最快的家用光枪方案
  （[GUN4IR 官网](https://www.gun4ir.com/pages/about-the-gun4ir%C2%AE)）。
- **精度**：街机级；4 点定位可解算枪口姿态，边缘精度优于双点方案。
  已知问题：指向屏幕边缘时精度会下降（[flycast issue #1175](https://github.com/libretro/flycast/issues/1175)）。
- **价格**：DIY 授权约 $10–20 起，全套物料约 $60–100；成品套件更高。
- **平台支持**：输出是标准 USB HID 鼠标，**天然兼容任何接受鼠标输入的系统（含 Android）**，
  无需专有驱动——这是相对 Sinden 的最大优势。
- **对本项目的意义**：开源、可自研量产、Android 友好。缺点是需要在屏幕四角布置红外灯
  （外置小硬件），DIY 授权的**商业使用受许可证限制**，量产需与作者谈授权或自研等价方案。

### 2.3 Ultimarc AimTrak（红外感应条方案）

- **原理**：枪内红外传感器 + 屏幕上方一条 USB 供电的红外 LED 条（相当于 Wii 感应条的反置：
  光源在屏幕侧，接收器在枪内）。枪端硬件完成坐标解算，**模拟成 USB 鼠标/手柄，无需驱动**
  （[Ultimarc AimTrak 官方页](https://www.ultimarc.com/light-guns/aimtrak-light-gun/aimtrak-light-gun-with-recoil/)）。
- **精度**：Batocera 光枪兼容性表给出 **2/5 星**，且"校准问题较多，往往需要多次校准才生效"；
  要求玩家距离屏幕 2–2.5 倍屏幕宽度（[Batocera 光枪指南](https://wiki.batocera.org/emulators:lightgun_games)）。
  大屏/投影场景下精度问题在社区中被反复报告
  （[ArcadeControls 大屏讨论帖](http://forum.arcadecontrols.com/index.php?topic=144232.0)）。
- **价格**：无后坐力 $95、带后坐力 $120–160；红外条另计 $45 左右
  （[Arcade Renovations](https://www.arcaderenovations.com/aimtrak-light-gun-blue.html)、
  [customgamingcreations](https://www.customgamingcreations.com/product/ultimarc-aimtrak-light-gun-without-recoil/)）。
- **平台支持**：USB 鼠标模拟，Android 可用。
- **对本项目的意义**：成熟商用件，可直接采购集成；但精度与口碑是三类摄像头/红外方案中较弱的，
  做"街机手感"卖点有风险。

### 2.4 Wii Remote + 红外感应条（蓝牙方案）

- **原理**：Wii Remote 内置 PixArt 红外摄像头，追踪感应条上两个红外光源；
  通过蓝牙连接主机。Mayflash DolphinBar 可把感应条 + 蓝牙适配器合一，
  并把 Wii Remote 模拟成鼠标（[Batocera DolphinBar 文档](https://wiki.batocera.org/hardware:dolphinbar)）。
- **精度**：原生两点定位**不感知枪口旋转与距离**，俯仰/偏航之外没有透视校正，
  指向与屏幕坐标的映射是近似拟合，准星需要屏幕内显示辅助；社区评价
  "没有屏幕准星就不够准"（[LaunchBox 论坛](https://forums.launchbox-app.com/topic/72445-wiimote-as-light-gun-without-dolphin-bar/)）。
  改进方案 Lichtknarre 用 2/4 个红外 LED 做几何校正，可把未改装 Wii Remote 校准到"瞄具级"精度
  （[ArcadeControls Lichtknarre 帖](https://forum.arcadecontrols.com/index.php?topic=167028.200)）；
  Dolphin 模拟器在蓝牙直通模式下可消除指针漂移误差
  （[Dolphin 指南](https://www.reddit.com/r/DolphinEmulator/comments/1in3glh/guide_using_real_wii_remotes_on_dolphin/)）。
- **成本**：二手 Wii Remote + DolphinBar 合计约 ¥150–250，是最便宜的可用方案。
- **平台支持**：Android 蓝牙 HID 可识别 Wii Remote，但 RetroArch Android 端对
  光枪输入的支持长期不完善（见 5.1）。Dolphin 在 Android（Shield TV 等）上可用。
- **对本项目的意义**：**供应链成熟（存量巨大）、成本低**，适合作为入门款外设；
  但需要软件层做 4 点校正算法才能达到光枪级体验，否则只是"空中指针"。

### 2.5 陀螺仪 + 加速度计空中指针（空中鼠标）

- **原理**：用 MEMS 陀螺仪测角速度、加速度计测重力方向，积分得到指向变化，
  映射为屏幕指针。各类"空中飞鼠"遥控器、手机体感遥控皆属此类。
- **精度**：**根本性不足**。陀螺仪积分必然漂移，需要不断用加速度计/地磁校正；
  且只能测"相对转动"，无法感知枪口相对屏幕的绝对位置——玩家平移枪口而不转动时指针不动。
  社区共识是红外指针方案远比陀螺仪精确（[Famiboards 讨论](https://famiboards.com/threads/ir-pointer-or-gyro-aiming.12583/)）。
  DIY 实验（Arduino + GY-521 模块做空鼠打光枪游戏）结论同样是"能玩但不像光枪"
  （[hobbytronics 博客](https://hobbytronics.home.blog/2020/07/11/airmouse-for-light-gun-games/)）。
- **对本项目的意义**：仅适合作为**零成本的兜底输入**（手机 App 当枪、体感遥控器），
  不能作为主打体验。街机光枪游戏弹道判定以像素计，空中鼠标的误差会导致"指哪打不到哪"。

### 2.6 顶置摄像头视觉方案

- **原理**：电视顶部放一颗摄像头，拍摄玩家手中的枪（带红外/可见光标记点或识别枪管轮廓），
  视觉算法解算指向。这是 Xbox Kinect / PS Move 思路的延续。
- **现状**：没有形成主流的开箱即用产品；最新的商用案例是**把摄像头放回枪内 + AI 识别屏幕**
  （见 2.7 G'AIM'E），即"摄像头在枪端"再次成为主流。顶置摄像头方案受遮挡、环境光、
  多人遮挡影响大，工程化难度高。
- **对本项目的意义**：如果自研，"枪内摄像头 + 屏幕侧标记"的信噪比与标定难度都优于
  "顶置摄像头 + 枪侧标记"，不建议走顶置路线。

### 2.7 市售"电视游戏枪"产品与 G'AIM'E

**G'AIM'E（Tassei Denki × Bandai Namco 授权）** 是目前最重要的参照产品：

- 即插即用光枪主机套装，内置《Time Crisis》《Point Blank》《Steel Gunner 1/2》等
  南梦宫经典街机游戏（[Retro Dodo 上手](https://retrododo.com/a-day-with-gaime/)、
  [Time Extension 报道](https://www.timeextension.com/news/2025/10/the-gaime-ai-powered-time-crisis-light-gun-is-up-for-pre-order)）。
- 技术：**枪管前端内置高分辨率摄像头，配合 AI 图像识别**直接识别电视/投影屏幕的位置与内容，
  不需要红外条、不需要白边框软件、不需要手动校准，支持 15–150 英寸显示设备，
  玩家移动后自动重校准（[A9VG 报道](https://www.a9vg.com/article/243102)、
  [网易/今日头条报道](https://www.toutiao.com/article/7512496832426017330)、
  [GamesPress 官方新闻稿](https://www.gamespress.com/Its-GAIME-Time---GAIME-TIME-CRISIS-Lightgun-System-in-Limited-Stock-an)）。
- 制造商 Tassei Denki 是为 Sony/Nintendo/Microsoft 做授权外设代工的日本厂商，
  工厂在深圳与越南（[gamescom 展商页](https://www.gamescom.global/en/exhibitor/tassei-denki)）——
  说明该方案 BOM 可控、可量产。
- Kickstarter 众筹远超目标，2025 年 11 月起发货，售价区间约 $99–199（不同套装）。
  评测普遍认可其"在现代电视上真正可用"（[MP1st 评测](https://mp1st.com/reviews/gaime-review-lightgun-fun-on-the-flatscreen)、
  [T3 上手](https://www.t3.com/tech/gaming-consoles/gaime-time-crisis-lightgun-system-first-hands-on-review)）。

**淘宝/抖音的廉价"电视游戏枪/体感枪"**：此类产品绝大多数是
**空中鼠标（陀螺仪）或简易红外指针**方案，配合内置安卓盒子的体感小游戏销售；
真正采用"枪内摄像头 + 屏幕边框识别"（Sinden 同源）的国产低价枪也存在
（AliExpress 上有对标 GUN4IR/Sinden 的成品枪，见
[AliExpress 光枪测评](https://www.aliexpress.com/s/wiki-ssr/article/light-gun-game)），
但普遍需要 PC 端驱动，**面向 Android 电视直接可用的成熟国产方案目前基本是空白**——
这正是本项目的机会窗口。国内玩家社区对"电视上玩光枪"的需求长期存在，
知乎相关问题的回答至今仍停留在"Wii 直柄模拟空中飞鼠，体验不佳"的层面
（[知乎：现在电视机有什么办法玩光枪游戏](https://www.zhihu.com/question/364067659)）。

## 3. 输入延迟链路分析

### 3.1 链路逐段拆解

整条链路：**光枪传感器 → 枪端解算 → 传输（蓝牙/USB）→ Android 输入栈 →
翻译层/游戏引擎 → 渲染 → 电视显示输出**。

| 环节 | 典型延迟 | 说明与来源 |
|---|---|---|
| 枪端传感器+解算 | 4–16ms | GUN4IR 平均 4ms（[官网](https://www.gun4ir.com/pages/about-the-gun4ir%C2%AE)）；Sinden 60fps 追踪即 ~16ms 帧粒度 |
| 传输 | USB 1–8ms；蓝牙 10–30ms | USB HID 轮询 125–1000Hz；蓝牙 HID 受协议栈与省电策略影响明显，Wii Remote 蓝牙链路是三者中最长的一段 |
| Android 输入栈 | 5–15ms | InputReader/InputDispatcher + 应用事件分发，通常 1 帧内 |
| x86 翻译层（Box64+Wine） | 不确定，抖动为主 | 翻译层不直接给输入加固定延迟，但 CPU 负载升高会放大**帧时间抖动**，间接拖长输入到画面的帧数 |
| 渲染 + DXVK → Vulkan | 1–2 帧（16–33ms @60fps） | DXVK 异步管线可掩盖部分开销，但弱 GPU 上渲染本身就是瓶颈 |
| 电视显示延迟 | **游戏模式 10–20ms；普通模式 40–100ms+** | 电视的 MEMC/降噪/超分等画质处理是最大单段延迟，开游戏模式可大幅削减（[RTINGS 输入延迟测试方法论](https://www.rtings.com/tv/tests/inputs/input-lag)、[DisplayNinja 输入延迟科普](https://www.displayninja.com/what-is-input-lag/)） |

**端到端估算**：

- 理想情况（USB 枪 + 原生渲染 + 游戏模式电视）：4 + 5 + 10 + 16 + 15 ≈ **50ms**
- 实际情况（蓝牙枪 + Box64/Wine + DXVK + 普通模式电视）：16 + 25 + 15 + 50 + 60 ≈ **165ms 以上**

### 3.2 多少毫秒才"可玩"

- < 60ms：准星跟手，接近街机手感。
- 60–100ms：多数玩家可适应，节奏快的爆头/速射环节有感知。
- \> 120ms：明显"拖枪"，玩家会自发做提前量补偿，体验口碑崩坏。

关键事实：**街机光枪游戏与 CRT 时代不同，本就不是靠显示端零延迟运作的**——
准星位置由游戏逻辑维护，命中判定发生在游戏内坐标系，与电视何时把画面显示出来无关。
延迟影响的是**玩家的手感反馈环**（眼睛看到准星滞后于手），而不是判定正确性。
因此即使链路 80ms，游戏依然"判定准确"，只是手感打折扣。

### 3.3 街机光枪游戏的延迟容忍度

- **屏外 reload 机制**（Time Crisis 踏板、多数街机光枪"把枪移出屏幕开火换弹"）：
  判定的是"枪口是否指向屏幕外"这一**粗粒度事件**，对延迟极不敏感。
- **有掩体/节奏型玩法**（Time Crisis、Razing Storm）：敌人攻击有固定前摇节奏，
  玩家靠预判，容忍度中高。
- **速射/打移动靶**（Point Blank 部分关卡、Big Buck Hunter 移动猎物）：对手感最敏感，
  是延迟预算的主要约束。
- **结论**：目标应定在**端到端 ≤ 80ms**，其中可控项是：选 USB/2.4G 而非蓝牙、
  强制提示用户开启电视游戏模式、光枪坐标解算放在枪端 MCU（绕过主机 CPU 抖动）。

### 4.2 分档结论（能否跑 Box64 + Wine + DXVK 栈的 DX9 老游戏）

Winlator（Wine + Box86/Box64 + Mesa Turnip/Zink/VirGL + DXVK/VKD3D）已证明
"ARM Android 上跑 Windows x86_64 游戏"技术可行（[Winlator 官方文档](https://brunodev85-winlator.mintlify.app/introduction)、
[翻译层科普](https://heldgames.com/guides/translation-layers-explained)）。
但其性能标杆是**骁龙 8 系手机 + Adreno/Turnip 开源驱动**；电视芯片完全不在一个量级。

- **第一档（可用）**：**RK3588/S**。4×A76 @2.4GHz 是目前 ARM 电视/盒子领域 CPU 天花板
  （单核 Geekbench 6 约 950–1000，接近骁龙 855 水平），Mali-G610 MP4 有活跃的
  PanVK/Panfork Vulkan 支持。跑 DX9 时代（2005–2012）的街机 PC 移植游戏，
  经 Box64+Wine+DXVK 后有机会达到 720p 30–60fps。**是唯一值得押注的量产芯片。**
- **第二档（勉强/实验性）**：Pentonic 2000、S928X。前者 4×A76 但只装在高端电视里、
  不开放给第三方做盒子；后者单核 A76 + 四 A55，CPU 尚可，但**固件只暴露 32 位 ABI**
  （[AndroidPC.es 实测](https://androidpc.es/amlogic-s928x-comparativa/)），
  Box64 需要 64 位环境，基本判死刑（除非厂商定制 64 位固件）。
- **第三档（不够）**：Pentonic 700/800/1000、MT9679、海思 V811、S905X4 等
  A73/A55 级别芯片。Box64 指令翻译对单核性能极敏感，A73 @1.5–2.0GHz 跑 DX9 游戏
  大概率掉到个位数帧率；Mali-G31/G51/G52 的 Vulkan 驱动质量也差。
  **这些芯片只适合跑原生 Android 游戏或 RetroArch 级别模拟器，不适合 x86 翻译栈。**

### 4.3 关键瓶颈：Vulkan 驱动与 32 位 ABI 陷阱

1. **DXVK 依赖 Vulkan 1.1+ 且对驱动质量敏感**。Mali 公版驱动在电视 SoC 上的
   Vulkan 实现普遍只够 UI 渲染；Turnip 只支持 Adreno；Mali 侧靠 PanVK（开源，仅覆盖
   Valhall 架构即 G52/G57/G310/G610 以后），G31（Bifrost）无望。
   替代路径是 Zink（OpenGL→Vulkan）或 VirGL，再多一层损耗。
2. **32 位 ABI 陷阱**：Amlogic 多数出货固件只支持 32 位 userspace，
   Winlator/Box64 生态全部假设 64 位 ARM。选型时必须确认固件 ABI。
3. **内存**：Wine + Box64 + 游戏本体建议 ≥ 4GB，理想 8GB。
4. **散热**：盒子普遍无风扇，A76 大核满载 10 分钟后降频会直接反映为帧率腰斩。

## 5. 已有产品形态与社区动向

### 5.1 RetroArch / Batocera / EmuELEC 的光枪支持

- RetroArch 有统一的 Lightgun API，PC 端对 Sinden/GUN4IR/AimTrak/Wii Remote 支持完善
  （[Sinden Wiki RetroArch 页](https://www.sindenwiki.org/wiki/Retroarch)、
  [GBAtemp 光枪支持帖](https://gbatemp.net/threads/retroarch-lightgun-support.548089/)）。
- **Android 端明显落后**：RetroArch Android 的光枪输入长期只有触屏模拟，
  社区反馈"Shield TV 上没有任何光枪能正常工作"
  （[Libretro 论坛](https://forums.libretro.com/t/light-gun-games-on-shield-tv/20243)）；
  但 USB 鼠标输入是通的，因此 GUN4IR/AimTrak 这类"鼠标模拟"枪理论上可用，
  DolphinBar 鼠标模式同理（[HyperSpin 论坛](https://hyperspin-fe.com/forums/topic/15324-retroarch-wiimote-for-duck-hunt/)）。
- Batocera（x86 Linux）有完整光枪生态与兼容性表（[Batocera 光枪指南](https://wiki.batocera.org/emulators:lightgun_games)）；
  EmuELEC 在 Amlogic 盒子（S905X3/X4 等）上把 RetroArch 光枪带到了电视盒子，
  并有 Wii Remote 光枪配置文档（[EmuELEC Wiki](https://github-wiki-see.page/m/EmuELEC/EmuELEC/wiki/Wiimote-Lightgun-Guide)、
  [EmuELEC Releases](https://github.com/EMUELEC/EmuELEC/releases)）——
  证明"电视盒子 + 光枪玩模拟器光枪游戏"已被社区跑通，但**只覆盖模拟器库，不覆盖
  TeknoParrot 的 PC 基板街机游戏**。

### 5.2 Winlator 类 x86 翻译层在 Android 上的现状

- Winlator = Wine + Box86/Box64 + Mesa（Turnip/Zink/VirGL）+ DXVK/VKD3D，
  开源、迭代活跃，可在 Android 手机跑 DX9–12 游戏（[Winlator 官方文档](https://brunodev85-winlator.mintlify.app/introduction)）。
- 同类还有 GameHub、DroidDeck（FEX + Proton + Turnip）等
  （[翻译层对比](https://heldgames.com/guides/translation-layers-explained)）。
- 性能现实：骁龙 8 Gen 2/3 + Turnip 跑 DX9 老游戏可达流畅；**换到 Mali 电视芯片后，
  GPU 驱动与 CPU 单核双重降级**，且 TeknoParrot 本身还要在 Wine 之上再跑一层
  （TeknoParrot 是 Windows 兼容层而非模拟器，[Tech Insider 介绍](https://tech-insider.org/teknoparrot-setup-windows-2026/)），
  在 Batocera/ARM Linux 上经 Box86/Box64 跑 TeknoParrot 已被社区判定"性能开销过大，不可靠"
  （[arcadesystems.co.uk](https://arcadesystems.co.uk/blog/post/teknoparrot-on-batocera-setup)）。
- **结论：TeknoParrot 游戏 → Android 的路径不是"移植 TeknoParrot"，
  而是"Box64 + Wine + DXVK 直接跑游戏本体 + 自研 I/O 钩子替代 TeknoParrot 的 JVS/输入模拟层"。**
  这是工程量最大、但也是唯一能做出产品级体验的技术路线。

### 5.3 TeknoParrot 有无 Android 移植动向

- 官方无任何 Android 移植计划；TeknoParrot 是 Windows-only 兼容层
  （[Tech Insider](https://tech-insider.org/teknoparrot-setup-windows-2026/)）。
- 社区方向是反过来的：把 TeknoParrot 搬到 x86 Linux（Batocera 集成，兼容率约 80–90%
  经 Wine 翻译，[arcadesystems.co.uk](https://arcadesystems.co.uk/blog/post/teknoparrot-on-batocera-setup)），
  以及 Nix 包化尝试（[nix-winery](https://github.com/monyarm/nix-winery)）。
- 没有任何公开项目在做"TeknoParrot on ARM/Android"。**本产品在内容运行层没有现成轮子，
  属于真正的前沿整合工程。**

## 6. 可行产品形态建议

### 方案 A：纯 Android App + 自研光枪外设（主推）

- **形态**：电视/盒子上安装一个 App（内置 Box64+Wine+DXVK 运行时与游戏管理器），
  搭配自研光枪（枪端 MCU + PixArt 类红外摄像头 + 屏幕四角红外灯，GUN4IR 同源思路，
  枪端完成坐标解算，以 USB HID / BLE HID 鼠标 + 手柄复合设备输出）。
- **优点**：外设毛利高、体验可控（枪端解算不依赖主机算力与延迟）、
  软件可分发给存量 RK3588 盒子用户。
- **核心难点**：
  1. Wine 之上替代 TeknoParrot 的 I/O 模拟（JVS/串口/加密狗模拟、游戏特定补丁）——
     每款游戏都是一次逆向工程；
  2. 游戏版权与分发合规（街机 ROM/游戏数据不可随产品分发）；
  3. 光枪硬件量产（结构、后坐力电磁铁、红外灯部署的用户教育）。

### 方案 B：定制盒子硬件 + 光枪套装（对标 G'AIM'E）

- **形态**：RK3588S 定制盒子（64 位 Android/Linux 双系统，8GB RAM，主动散热）
  + 双枪 + 踏板 + 红外灯组，开箱即用，预装前端。
- **优点**：体验完全可控，可做到 G'AIM'E 级"插上电视就玩"；
  G'AIM'E 已验证该形态的市场与定价（$99–199）（[GamesPress](https://www.gamespress.com/Its-GAIME-Time---GAIME-TIME-CRISIS-Lightgun-System-in-Limited-Stock-an)）。
- **核心难点**：
  1. 硬件 BOM 与供应链（RK3588 板 + 枪 + 灯 + 踏板，整机成本需压到 ¥600 内才有竞争力）；
  2. 散热与性能调校（翻译栈吃满 CPU，无风扇设计会降频）；
  3. 与方案 A 相同的 I/O 模拟工程量，一款游戏一款游戏地适配。

### 方案 C：串流方案（PC 端跑 TeknoParrot，电视端串流 + 本地光枪）

- **形态**：用户家里已有一台能跑 TeknoParrot 的 PC；电视端 App 只做
  Moonlight/Sunshine 串流客户端 + 把本地光枪坐标回传为 PC 鼠标输入。
- **优点**：彻底绕开 ARM 翻译栈的性能与兼容性问题，第一天就兼容整个 TeknoParrot 库；
  软件工程量最小，可最快上线验证市场。
- **核心难点**：
  1. **延迟链最长**：光枪 → 电视 → 网络回传 PC → PC 渲染 → 编码 → 网络 → 电视解码显示，
     局域网内现实端到端 60–120ms，恰在可玩边缘；需靠枪端低延迟（4ms 级）和
     电视游戏模式把预算抢回来；
  2. 依赖用户已有 PC，受众收窄到核心玩家，不是大众产品；
  3. 准星渲染位置的选择（PC 端渲染准星则延迟可见，电视端叠加准星则与游戏判定可能不一致）。

### 路线建议

**C 先行验证（3 个月量级）→ A 做主力产品 → B 作为旗舰 SKU。**
光枪硬件（枪端解算 + HID 输出）是三个方案共用的资产，应最先投入。

## 7. 结论速览

1. **输入方案首选"枪端红外摄像头 + 屏幕标记点、枪端 MCU 解算、HID 鼠标输出"**
   （GUN4IR 路线）：4ms 级延迟、Android 免驱、可自研量产。Sinden 路线精度更高
   但依赖主机端视觉驱动且 Android 仅原型级；陀螺仪空鼠不可用；G'AIM'E 的
   "枪内摄像头 + AI 识别屏幕"验证了更高阶的可行性。
2. **延迟预算 80ms**：枪端 4ms + USB 5ms + Android 栈 15ms + 渲染 33ms +
   电视游戏模式 15ms 可达；蓝牙传输和非游戏模式电视是两大延迟黑洞。
3. **芯片只有 RK3588 一档够用**：4×A76+Mali-G610 是 Box64+Wine+DXVK 跑 DX9
   街机游戏的底线；Amlogic S928X 死于 32 位 ABI；A73/A55 级电视芯片全部不够。
4. **TeknoParrot 无 Android 移植动向**，可行路径是 Winlator 式翻译栈直跑游戏本体
   + 自研 I/O 钩子，或先做 PC 串流方案规避。
5. **市场窗口存在**：G'AIM'E 众筹成功验证需求，国产低价"电视游戏枪"均为空鼠方案，
   电视端真光枪 + 街机光枪游戏库的组合目前是空白。
