## 1. 核心认知（先纠正一个概念）

**TeknoParrot 不是传统意义的"模拟器"，而是兼容层（compatibility layer）。**

这批游戏对应的街机基板（Taito Type X、Sega RingEdge/Lindbergh、Namco ES3 等）本质就是普通 x86 PC + Windows XP/7 Embedded（或 Linux），游戏本体是原生 x86/x64 可执行文件。TeknoParrot 做的是：

1. 注入 DLL、按游戏打内存补丁（绕过加密狗/联网认证/硬件自检）；
2. 模拟街机 I/O 板（JVS 串口协议）、读卡器、投币器；
3. 补丁分辨率/显卡检测，统一输入映射。

**这对方案是重大利好**：我们不需要在 Android 上"模拟街机主板"，只需要解决两个工程问题：

- **A. 在 ARM Android 上运行 x86 Windows/Linux 程序**（翻译栈，已有成熟开源生态）；
- **B. 重写 TeknoParrot 的 I/O 兼容层**（JVS 模拟、投币、光枪映射、每游戏补丁）。

其中 B 的一半是开源的：OpenParrot（GPL-3.0，覆盖 102 个 Taito Type X 系游戏）可以直接读源码移植；另一半（闭源 `TeknoParrot.dll` 内 217 个游戏的硬编码补丁）需要按游戏逐个逆向复刻——这是工作量最大的部分。

**源码级利好证据**：OpenParrot 官方源码中已存在 Wine/Android 适配分支（`TP_LOADER_MANAGED_INIT`、`TP_CRC_NORMALIZE_LAA` 注释明确提到 Wine/Box64/Android 启动场景、TypeX2 的 `...ResampleLoopAndroid` 补丁）——官方自己都在往这个方向走，技术路线已被验证。

## 2. 28 款游戏的分组与对应路线（详见文档 02）

| 组 | 数量 | 特征 | Android 路线 | 难度 |
|---|---|---|---|---|
| A. Windows x86 + DirectX 9 | 16 | XP Embedded 时代，最高 C2D+7600GS 级需求 | Box64 + Wine + DXVK/D8VK | ★★ |
| B. Windows x64 + DirectX 11（Unity） | 3 | Point Blank X 等，1080p，性能分水岭 | 同上但要求骁龙 8 系 GPU | ★★★★ |
| C. Linux ELF（Lindbergh 等） | 4 | 幽灵特警进化、原始狩猎、Go Go Strike、Family Guy Bowling | **Box64 直跑 + lindbergh-loader**（无需 Wine！） | ★★ |
| D. PS2 基板（System 246） | 1 | 吸血鬼之夜 Vampire Night | NetherSX2（AetherSX2 fork） | ★★★ |

**关键洞察：C 组（Linux ELF）在 Android 上是最好做的**——Android 本身就是 Linux，Box64 可以直接翻译执行 x86 Linux ELF，开源项目 `lindbergh-loader` 已经实现了 Lindbergh 基板的全部 I/O 模拟且本就支持 ARM。建议拿 C 组做第一个打通的里程碑。

**B 组是性能分水岭**：Unity DX11 1080p 需要 Vulkan 1.3 级 GPU 驱动，只有骁龙 Adreno（Turnip 开源驱动）达标，这直接决定了硬件选型（见第 4 节）。

## 3. 推荐总体架构

```
┌─────────────────────────────────────────────────┐
│  启动器 App（Android 原生，Kotlin/Java）           │
│  游戏列表 / 按键映射 / 光枪校准 / 设置 / OTA        │
├─────────────────────────────────────────────────┤
│  自研兼容层 "ParrotDroid"（C/C++，核心工作量）      │
│  ├─ JVS I/O 模拟（移植自 OpenParrot，GPL）        │
│  ├─ 每游戏补丁集（profile 数据可复用，补丁需复刻）   │
│  ├─ 光枪/投币/按键 → 游戏输入映射                  │
│  └─ NVRAM/存档文件化                              │
├──────────────────────┬──────────────────────────┤
│ Windows 游戏链        │ Linux ELF 游戏链          │
│ Box64 → Wine 10      │ Box64 + lindbergh-loader │
│ → DXVK → Vulkan      │ → OpenGL → gl4es/原生GL   │
├──────────────────────┴──────────────────────────┤
│  光枪外设：枪内红外摄像头 + 屏幕标记点，             │
│  枪端 MCU 解算，USB HID 绝对坐标鼠标输出（免驱）     │
└─────────────────────────────────────────────────┘
```

三条执行链分流（对应 TeknoParrot 的 EmulatorType 概念）：
- **Windows 链**：以 Winlator 为代码基座（它已整合 Box64+Wine+DXVK+Turnip），裁剪掉通用性，专注固定游戏列表做深度适配。
- **Linux 链**：Box64 + lindbergh-loader，轻量，无需 Wine。
- **PS2 链**：仅 1 款，直接集成 NetherSX2，优先级最低。

## 4. 硬件选型结论（详见文档 03/04）

**GPU 驱动是整个方案的生死线**，不是 CPU 算力：

| 芯片 | GPU / Vulkan 现状 | 结论 |
|---|---|---|
| 骁龙 8 Gen 2 / 8s Gen 3 / 8 Elite（开发板/盒子） | Adreno + Turnip 开源驱动，Vulkan 1.3 ✅ | **首选**，实测 GTA V 45-60 FPS，DX9 老游戏绰绰有余 |
| RK3588 / RK3588S | Mali-G610，PanVK 2025 年才过 Vulkan 1.2，不成熟 | 次选/观望，可做 A 组 DX9 游戏的验证机 |
| Amlogic S905X4 / S928X | Mali-G31/G52，PanVK 不支持 Bifrost；S928X 固件仅 32 位 ABI | ❌ 不可行 |
| 普通智能电视内置芯片（MT96xx、A73/A55 级） | 算力+驱动双不足 | ❌ 不做本地运行，只作串流客户端 |

**产品形态建议（三档）**：
1. **旗舰：自研盒子**（骁龙 8 系开发板方案或 RK3588 起步）+ 自研光枪套装，软硬一体，体验可控。
2. **轻量：纯 App**，适配已有骁龙 8 系设备（手机/平板/高端盒子），光枪外设单独销售。
3. **保底：串流方案**（PC 跑现有 TeknoParrot + Sunshine → 电视 Moonlight，光枪直连 PC 端零延迟回传）——成本最低，建议**用它先做市场验证**，同时作为低端电视用户的兜底。

**光枪方案**：采用 GUN4IR 开源路线（枪内红外摄像头 + 屏幕四角/边框标记点 + 枪端 MCU 解算 + USB HID 绝对坐标输出），平均延迟约 4ms、Android 免驱、可量产自研。Sinden 精度更高但需主机端视觉驱动、Android 支持仅为原型；陀螺仪空鼠方案精度不足以通过光枪游戏判定。端到端延迟预算 ≤80ms，主要黑洞在蓝牙传输和电视非游戏模式，须强制要求"游戏模式"。

## 5. 开发路线图（落地排期）

### 阶段 0：技术验证（4-6 周，1-2 人）
目标：证明"骁龙 8 系设备 + 翻译栈"能跑通 3 款代表游戏。
- 采购验证机：骁龙 8 Gen 2 以上设备 1 台 + RK3588 开发板 1 块。
- 用现成 Winlator 直跑：**Go Go Strike**（Linux，最简）、**一款 A 组 DX9 游戏**（如 After Dark/Wartran）、**Point Blank X**（B 组天花板）。记录帧率、输入、存档表现。
- 光枪原型：GUN4IR 套件或先用普通鼠标验证绝对坐标输入链路。
- **产出：可行性报告 + 三款游戏的性能数据**。这一步不通过，后续全部重估。

### 阶段 1：兼容层自研 MVP（8-12 周，2-3 人）
- Fork OpenParrot（GPL-3.0），移植 JVS/FastIO 模拟与输入映射到 Wine 环境（OpenParrot 已有 Wine 适配分支，顺着官方路线走）。
- 复刻本地 28 款游戏的补丁集：优先 OpenParrot 开源覆盖的；闭源 `TeknoParrot.dll` 的游戏需逆向（每款约 1-5 天，取决于保护复杂度）。
- Linux 链：集成 Box64 + lindbergh-loader，打通 C 组 4 款。
- **产出：10 款游戏可玩（覆盖 A/C 两组），光枪可用，投币/存档正常。**

### 阶段 2：产品化（12-16 周，3-5 人）
- Android 启动器 App：游戏库、按键映射 UI、光枪校准向导、云存档。
- 每游戏 profile 数据体系（复用 TeknoParrot GameProfiles 的数据结构）。
- 光枪外设量产化（ID/结构/PCBA/固件）。
- OTA 更新、崩溃上报、兼容性矩阵自动化测试。
- **产出：28 款全覆盖（B 组按骁龙 8 系达标），软硬一体可发货。**

### 阶段 3（可选）：串流产品线（4-6 周并行）
- Sunshine 服务端一键安装包 + 电视端定制 Moonlight + 光枪直连 PC 方案。

## 6. 风险清单（按严重度排序）

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | **闭源补丁集复刻工作量**：217 个游戏的补丁在 `TeknoParrot.dll` 里闭源，本地 28 款中走 TeknoParrot 链的需逐个逆向 | 工期不可控 | 阶段 0 先盘点 28 款各走哪条链；优先选 OpenParrot 开源覆盖的游戏做首发阵容 |
| 2 | **GPU 驱动绑定骁龙**：只有 Adreno+Turnip 满足 Vulkan 1.3 | 硬件成本/供应链 | 旗舰用骁龙；跟踪 PanVK 进度，RK3588 做二供 |
| 3 | **法律合规**：游戏 ROM 版权、商标（尤其商用出货） | 产品下架/诉讼 | 硬件和软件不捆绑 ROM；与版权方洽谈授权（光枪游戏版权分散在 Sega/Namco/Raw Thrills 等）；参考 Analogue/RetroTink 的"不附带 ROM"模式 |
| 4 | **GPL-3.0 传染性**：OpenParrot/lindbergh-loader 是 GPL，衍生作品需开源 | 商业模式 | 兼容层单独开源（反哺社区反而有利），闭源部分只做启动器 App 与外设固件 |
| 5 | 光枪延迟实测不达标 | 体验崩坏 | 阶段 0 原型实测；屏幕标记点方案兜底精度 |
| 6 | 每游戏兼容性长尾（shader 修复、区域补丁等，参考本地 Patches 目录的 AMD/Nvidia 分别修复） | 售后成本 | 建立每游戏兼容性矩阵 + 自动化回归 |
