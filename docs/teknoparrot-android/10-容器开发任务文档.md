## 1. 产品定义

ParrotDroid：Android 电视/盒子上的街机光枪游戏容器。开机进游戏库 → 选游戏即玩 → 手机光枪（tvgun）瞄准射击。技术基座 = fork Winlator（Box64 + Wine + DXVK + Turnip），锁定骁龙 Adreno 设备。

**与通用 Winlator 的区别**：固定游戏列表、免设置、光枪输入直注、电视 D-pad UI、白边框定位叠加、每游戏 I/O 兼容配置内置。

## 2. 关键架构决策（已定）

1. **输入注入走 XServer 层**（文档 09 已证实）：
   - `XServer.injectPointerMove(int x, int y)`（XServer.java:148，线程安全，绝对坐标）
   - `XServer.injectPointerButtonPress/Release(Pointer.Button.BUTTON_LEFT)`（:164/:173）
   - 容器 screenSize 固定 1920×1080 → 与 tvgun 规范坐标 **1:1 直通，零换算**。
   - 接入：fork 后新建 `LightGunInputManager`（UDP 收包线程，仿 `WinHandler` 写法），在 `XServerDisplayActivity.onCreate()` 创建、onDestroy 停止。**协议解析直接复用 tvgun-tv 的 `com.tvgun.tv.core` 包源码**（AimSlot/Protocol/UdpAimReceiver/DiscoveryResponder/MiniHttpServer），把 InputSink 实现接到 XServer.inject* ——即 tvgun-tv 里预留的 `ContainerSink` 的真实落地。
   - 备用双发通路：`WinHandler.mouseEvent()`（UDP→winhandler.exe→Windows mouse_event，`MouseEventFlags.ABSOLUTE=0x8000` 已定义未被使用），个别游戏 X 层注入不灵时用。
2. **白边框**：复用 tvgun-tv 的 `BorderOverlayView`，叠加在 XServerDisplayActivity 的根布局（FrameLayout addView 置顶），常显。游戏以客户区对齐全屏，坐标系天然一致。
3. **两条游戏执行链**：
   - Windows 链（A/B 组 24 款）：Winlator 容器内跑 exe + 每游戏兼容配置（见第 4 节）。
   - Linux 链（C 组 4 款 Lindbergh 等）：**Box64 + lindbergh-loader 直跑，不经 Wine**。lindbergh-loader 开源且支持 ARM，是独立的轻量 pipeline，单独里程碑。
   - PS2 链（Vampire Night 1 款）：NetherSX2，最低优先级。
4. **许可**：Winlator 是 **LGPL-2.1**——fork 的修改必须开源（对我们没影响，兼容层本来就计划开源反哺社区，闭源部分只做启动器与商业层）。内置组件各自许可见文档 09 第 4 节。
5. **硬件锁定**：骁龙 8 系（Adreno + Turnip，Vulkan 1.3）。Mali 设备靠 Vortek 包装层，兼容性不可控，不做首发支持。

## 3. 里程碑与任务

### C0 可行性验证（本阶段，无需硬件）

### C1 ParrotDroid App 骨架（2-3 周，1-2 人，无需硬件）
目标：fork Winlator 裁剪出产品形态空壳，PC 模拟器/手机上可安装进 UI。
- C1.1 fork winlator-src → D:\yinwu\container\parrot-droid（独立 git 管理或 subtree，**不并入 yinwu 仓库**，避免大文件；在 yinwu 仓库只保留补丁脚本与文档）。建立"上游同步"策略（记录基线 commit，改动全部收口在 `com.parrotdroid.*` 包 + 最小侵入点清单）。
- C1.2 裁剪（文档 09 第 5 节清单）：移除通用设置 UI/输入控制编辑器/容器管理向导，保留容器运行时、XServer、组件解压。游戏库改为读取内置游戏清单（复用 tvgun-bridge 的 games/*.json 适配数据，扩充容器字段：screenSize、DXVK 版本、环境变量、Box64 preset）。
- C1.3 电视化主界面：横向游戏墙（图标用 1846\Icons\ 的 PNG）、D-pad 导航、选中即启动。
- C1.4 集成 tvgun-tv core 包 + LightGunInputManager + BorderOverlayView（无游戏时可先叠加在测试画面）。
- **验收**：APK 装机后进游戏墙；手机 App 自动发现连上；边框显示；injectPointerMove 驱动的准星在测试画面可见且跟随。

### C2 首款游戏打通（3-4 周，1-2 人，需骁龙 8 系设备）
目标：Ghost Squad Evolution 或一款 DX9 游戏可玩。
- C2.1 采购验证机（见第 5 节硬件清单）。
- C2.2 游戏导入链路：游戏目录打包（zip/直拷私有目录）→ 容器 wine 前缀部署 → 启动参数配置。
- C2.3 兼容层策略（按游戏分组，见文档 06）：
  - **OpenParrot 覆盖的游戏（Type X 系）**：容器内直接跑 OpenParrotLoader + OpenParrot.dll（官方已有 Wine 适配分支，文档 01 第 7 节）——优先选这类做首发。
  - **TeknoParrot.dll 闭源链的游戏**：两条路——a) 在 Wine 里跑 TeknoParrot.dll（需复刻其加载器，工作量大）；b) 逐游戏逆向复刻补丁到自研 shim（每款 1-5 天）。先选 a 验证，不行再 b。
  - **Lindbergh 链**：本里程碑若选 GSEVO 则走 C4 的 Linux pipeline 提前验证。
- C2.4 输入全链路：手机光枪 → LightGunInputManager → injectPointer → 游戏内准星。校准（复用 tvgun-tv 两点校准）→ 量程映射（profile xAxisMin/Max 语义，参考文档 06）。
- **验收**：GSEVO 或首发游戏"投币→开始→命中→换弹→退出"全流程；静止抖动与 PC 桥接版同量级；720p/1080p 帧率 ≥30fps。

### C3 游戏阵容扩展 + 产品化（4-6 周，2-3 人）
- C3.1 按 02 文档分组推进 27 款适配（优先级：OpenParrot 开源链 > DX9 轻量 > DX11 Unity）。
- C3.2 兼容性矩阵 + 自动化回归（每游戏固定脚本：启动→注入序列→截图比对）。
- C3.3 产品化：游戏包 OTA 分发、崩溃上报、预测量按电视延迟档位预设（predictMs 90→130ms）、双枪（按来源 IP 分槽）。
- **验收**：≥10 款可玩，每款有适配卡；连续 2 小时稳定性。

### C4 Lindbergh Linux 链（2-3 周，1 人，可与 C3 并行）
- C4.1 编译 box64 + lindbergh-loader for Android（NDK 交叉编译或 Termux 环境预编译打包）。
- C4.2 打通 GSEVO/Primeval Hunt 的 ELF 直跑（无 Wine，性能开销最小）。
- C4.3 输入对接同 C2.4（lindbergh-loader 的输入配置文件生成）。

### C5 PS2 链（Vampire Night，1 周，低优先级）
- 集成 NetherSX2 + 光枪（nuvee/USB 插件路径），单独 Activity。

## 4. 每游戏容器适配卡（模板，C2 起逐款填写）

|---|---|

| 容器配置 | screenSize、DXVK 版本、Turnip 版本、env vars、Box64 preset |

| 验收脚本 | 自动化注入序列 + 截图比对基线 |

## 6. 风险清单（本线特有）

| 风险 | 等级 | 对策 |
|---|---|---|
| Winlator 本机/CI 构建链不稳（NDK/gradle 依赖） | 中 | C0.1 就是验证这个；阻断则转 Termux 侧载方案或 Mobox 基线 |
| TeknoParrot.dll 闭源补丁复刻工作量 | 高 | 首发阵容只选 OpenParrot 开源链 + Lindbergh 链游戏（合计约 10+ 款），闭源链逐款评估 |
| Wine 下反作弊/保护（部分游戏有 VMProtect 类保护） | 中 | C2 逐款实测，死的游戏降级为串流方案 |
| Turnip 与个别游戏 shader 不兼容 | 中 | 社区修复包先例（本地 Patches 目录）；DXVK 版本可回退 |
| 上游 Winlator 大版本变动 | 低 | fork 侵入点收口 + 基线 commit 固定，季度评估同步 |
| LGPL-2.1 合规 | 低 | fork 仓库公开，商业层（启动器/账号/分发）与容器进程隔离 |

## 7. 与既有资产的复用关系

```
tvgun（手机 App）        ——零改动，协议不变
tvgun-tv/core 包        ——源码级并入 ParrotDroid（协议/校准/映射/发现）
tvgun-tv BorderOverlayView ——叠加在容器显示 Activity
tvgun-bridge games/*.json ——游戏适配数据扩充容器字段后共用
1846/GameProfiles + Icons ——游戏库数据源（量程/图标/平台信息）
1846/OpenParrotWin32/x64  ——容器内 Type X 链的运行时（开源链游戏）
```
