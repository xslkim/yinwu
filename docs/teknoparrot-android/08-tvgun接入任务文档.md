## 1. 目标与范围

把 D:\tvgun 手机光枪系统（手机摄像头识别屏幕白边框 + 陀螺仪融合，解算枪口指向坐标）作为光枪输入，接入 D:\yinwu 下 TeknoParrot 运行的街机光枪游戏。

- **第一阶段（本文档重点）**：PC 平台。手机 → 局域网 → PC 桥接程序 → TeknoParrot 游戏。
- **第二阶段**：Android 电视平台。手机 → 局域网 → 电视端自研容器（Winlator 类）→ 游戏。架构预留，详细设计在第一阶段验收后展开。

## 2. 现状盘点（已确认的事实）

### 2.1 tvgun 手机端已具备

- 追踪器 v5.1 实测通过：Sinden 式亮边框 + 陀螺传播单应 + 逐边视觉校正，静止抖动 0.11px（1080p 规范坐标系），可用率 98-100%。
- **UDP 120Hz 上报**：文本 `"x,y"`（1 位小数，如 `"111.5,222.5"`）→ PC 8000/UDP；坐标为 `snapshotAhead(now, predictMs)` 的预测值（默认提前 90ms 补偿显示延迟）。
- **扳机**：点屏幕 = `POST /shot`，JSON `{"x":f,"y":f}`，**只有按下事件、没有松开事件**；期望响应 `{"hit":bool,"score":int}`（用于震动/闪屏反馈，不校验语义）。
- **自动发现**：手机向 8001/UDP 广播 `TVGUN_DISCOVER`，PC 应答 `TVGUN_HERE <port>`，零配置换机。
- **无其他按键**：没有换弹/开始/投币事件（音量键已被本地占用）。

| HTTP `/shot` 解析 | run_tv.py:189-211 | 简化：去掉队列阻塞，收到即触发 |

### 2.3 已确认的坑（必须在桥接器解决）

1. **坐标基准不一致**：手机 Tracker 检测的是白边框**外缘**（当规范坐标 0,0），而 run_tv.py 把边框**内缘**当 0,0 → 固定 ~13px 偏差；另有枪管-手机安装偏差 + 广角镜头 ~7px 偏差。**tvgun 侧两点校准未实现**（HANDOVER.md 待办 #1）→ 由桥接器做两点/四点校准统一吸收。
2. **扳机无松开事件** → 桥接器自己合成完整 click（down + 固定时长后 up）；泵动/长按类操作需映射策略。
3. **无投币/开始/换弹键** → 桥接器本地热键兜底 + 手机端协议扩展（第二阶段新增 HTTP 端点）。
4. **真实游戏画面不归我们渲染** → 白边框必须用置顶透明叠加窗口盖在游戏窗口上，游戏必须窗口化/无边框化（独占全屏下叠加必失效）。

### 2.4 TeknoParrot 侧输入链路（详见文档 06）

- 光枪游戏 profile 的 `GunGame=true` + `Input API=RawInput`：TeknoParrotUI 监听 RawInput，把设备绝对坐标归一化后按 profile 量程（`xAxisMin/Max` 等）写入共享内存 `TeknoParrot_JvsState`，注入的 OpenParrot/TeknoParrot.dll 伪装 JVS I/O 喂给游戏。
- **内置 `Windows Mouse Cursor` 伪输入设备**可直接吃系统光标位置——SendInput 注入的绝对坐标即走此路。
- DemulShooter（第三方光枪注入器，支持本地多款游戏）**只读本机 RawInput HID 设备，无网络入向接口**；但每枪一个虚拟 HID 设备它就能识别，且免费获得屏外换弹、双枪、后坐力输出。

│ snapshotAhead     │   POST /shot {x,y}        │   aim 槽 / shot 事件 / 发现  │
│ 点屏=扳机          │ ─────────────────────────▶ │                              │
└──────────────────┘   UDP 8001 发现            │ ② 坐标引擎                    │

### 3.1 输入注入路线决策（详见文档 06/07 的对比）

| 路线 | 原理 | 优点 | 缺点 | 定位 |
|---|---|---|---|---|
| **A. SendInput 绝对鼠标** | `MOUSEEVENTF_ABSOLUTE\|VIRTUALDESK` 移动系统光标 + 左键 click | 零驱动、普通权限、RawInput/DirectInput 均可见；TP 内置 Windows Mouse Cursor 直接吃 | 抢系统鼠标、只能单枪、带 INJECTED 标记（街机游戏不检测） | **POC / 首发** |
| **B. 虚拟 HID 绝对鼠标** | vmulti/VHF 驱动创建"绝对坐标 digitizer"设备，每枪一实例，桥接器喂报告 | 不占系统光标、双枪、TP 原生和 DemulShooter 通吃、无注入标记 | 要装内核驱动（签名），开发量+ | **产品化** |
| C. fork DemulShooter 加 UDP 源 | 扩展其输入层直接收网络包 | 后坐力输出等生态 | 绑定 DS 维护节奏，DS 无网络入向先例 | 备选补充 |

**决策：先 A 后 B**。A 一周内可打通全链路验证手感；B 作为产品化形态紧随其后（驱动签名需提前申请 EV 证书或使用测试签名模式验证）。

### 3.2 坐标映射与校准

- 叠加白边框画在游戏客户区**最外圈**（宽 24px，几何参数沿用 tvgun `BORDER_THICK=24`，不加 4% margin，减少画面遮挡）。
- 手机上报的规范坐标 (nx, ny) ∈ [0,1920]×[0,1080] 以边框外缘为基准 → 桥接器映射：
  `px = rect.left + (nx/1920)·rect.width`，`py = rect.top + (ny/1080)·rect.height`（rect = 游戏客户区屏幕坐标）。
- **两点校准**（桥接器内置校准模式）：屏幕显示两个校准靶点（建议左上/右下，避开边框带），用户各瞄准开一枪，解算仿射修正（平移+各向异性缩放），一次性吸收外缘 13px 偏差 + 枪管安装偏差 + 广角镜头偏差。校准数据按"手机序列号+镜头"持久化。
- SendInput 坐标换算：`(0.5 + px·65535/virtualW, 0.5 + py·65535/virtualH)`，virtual = `GetSystemMetrics(SM_CXVIRTUALSCREEN)`；桥接器进程声明 **Per-Monitor-V2 DPI 感知**；游戏窗口移动/DPI 缩放变化时重算。

### 3.3 TeknoParrot 侧配置（每游戏 profile）

- `Windowed=1`（必须，保证叠加边框可见）+ 桥接器把游戏窗口无边框化（去 WS_CAPTION/WS_THICKFRAME，铺满屏幕）；
- 光枪输入：路线 A 用 `Input API=RawInput` + TP 内置 Windows Mouse Cursor；路线 B 选对应虚拟 HID 设备；
- `HideCursor=1`（藏系统光标）；准星用 TP 自带 Crosshair（P1.png/P2.png）或游戏内建准星；
- 扳机=鼠标左键；换弹策略按游戏二选一：右键（桥接器热键/手机端新按键）或屏外开枪（桥接器把"瞄准屏外时的射击"映射到边框带外坐标）；
- 投币/开始：桥接器本地键盘热键（默认 5=投币、1=开始，可在桥接器 GUI 配置）。

## 4. 第二阶段（Android 电视）架构预留

- 电视端容器代码自控（Winlator 类）：桥接逻辑作为容器 App 的一个模块，收同样的 UDP/HTTP 协议 → 直接调容器内置输入分发（Winlator 式 injectPointer 喂给 X Server/Wine），**无需 root、无需 SendInput**。
- 白边框由容器 App 的 overlay 层画（SurfaceView 全屏容器上叠加）。
- 手机端 App **零改动**复用（自动发现协议不变）。
- 关键差异：电视显示延迟更大（游戏模式 20-50ms），手机端 predictMs 需按电视调大（90→130ms 档，已有旋钮）；第一阶段桥接器要把"预测量与显示链路标定"做成可测指标，第二阶段直接复用方法。
- 详细任务在第一阶段验收后立项。

## 6. 测试方案

1. **无手机回归**：`run_video_test.py`/`run_video_imu.py` 回放推送 aim/shot，脚本化断言注入坐标序列正确（桥接器记录注入日志比对）。
2. **坐标精度测试**：校准后系统遍历屏幕 5×5 网格靶点，手机逐点瞄准，记录误差分布（目标：P95 ≤ 8px @1080p）。
3. **延迟测试**：高速摄像机拍"手机甩枪→屏幕准星到位"（240fps），测端到端感知延迟（目标 ≤120ms 含显示）。
4. **游戏矩阵**：每款适配游戏跑标准流程清单（投币/开始/命中判定/换弹/BOSS 战/退出），记录适配卡。
5. **长时间稳定性**：连续运行 2 小时，aim 流无内存泄漏、注入无漂移。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 个别游戏窗口化后渲染异常（shader/分辨率写死） | 中 | 本地 Patches 目录已有社区修复先例；适配卡记录，问题游戏延后 |
| SendInput 被游戏窗口遮挡时 Z-order 竞争（叠加窗闪烁） | 低 | 叠加窗 NOACTIVATE + 每 500ms 重置顶；游戏无边框化 |
| 手机端无扳机松开事件导致扫射类游戏手感差 | 中 | 桥接器 click 时长参数化；M2 后扩展手机协议加"按住"事件（UDP 新消息类型，向后兼容） |
| 虚拟 HID 驱动签名成本/周期 | 中 | M3 提前启动 EV 证书采购；POC 阶段用测试签名 |
| 双枪时两部手机互相遮挡摄像头 | 低 | 产品阶段评估枪身支架；M3 先技术验证 |
| 校准漂移（手机在枪上的安装位移） | 低 | 校准向导做成 10 秒可重跑的流程，启动时提示 |

## 8. 工程落地信息

- **新工程位置**：建议 `D:\yinwu\tvgun-bridge\`（纳入 yinwu 仓库版本管理，注意 .gitignore 白名单需加目录）。
- **技术选型**：C# .NET 8 + WPF（叠加窗/注入/与 TeknoParrot 生态同源）；协议服务部分可参考 D:\tvgun\scripts\run_tv.py 的 Python 实现逐段翻译（协议细节见本文 §2.1/§2.2，全部已列明）。
- **依赖**：无第三方 NuGet 硬性依赖（SendInput 用 P/Invoke）；M3 起加 VHF/vmulti 驱动交互。
- **验收总标准（第一阶段）**：手机光枪在 5 款首发游戏中完成"自动发现→校准→投币→游玩→退出"全流程，瞄准 P95 误差 ≤8px，主观手感不劣于 tvgun 打鸭子演示。
